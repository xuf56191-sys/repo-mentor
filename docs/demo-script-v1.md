# RepoMentor V1.0 五分钟演示脚本

## 演示前准备（不计时）

```powershell
pip install -r requirements-ui.txt
$env:PYTHONPATH = (Resolve-Path .\src).Path
streamlit run app.py
```

准备一个不含隐私信息的小型本地仓库路径，以及一段可公开展示的手动 Issue。
不要在截图或录屏中展示 `.env`、API Key、用户名目录或私有远程地址。

## 0:00—0:40：问题与定位

讲解：初学者面对一个开源 Issue 时，真正缺少的不是任意仓库聊天，
而是“根据自己的基础，先读什么、练什么、怎样证明准备好了”。
RepoMentor 因此把检索当证据层，把学习闭环和贡献准备度当产品输出。

## 0:40—1:30：输入与范围

在侧边栏输入学习水平、已掌握技能、每天时间、本地仓库路径，
再手动粘贴 Issue 标题、描述、labels 和验收结果。

强调：系统不自动抓取 Issue、不扫描整个大型仓库、不修改代码。
缺少关键描述时 Pydantic/输入检查会阻止分析并在页面展示错误。

## 1:30—2:30：路线与证据

点击“生成贡献学习路线”，展示：

1. 每日阅读、代码定位和实践任务；
2. 每条任务的真实文件来源；
3. 证据表中的路径、符号和行号；
4. 输入一个当前模块问题，展示带 `文件:起止行` 的回答；
5. 输入一个明显无关问题，展示保守拒答。

解释一次性 `LearningEvidenceLayer`：路线、测验和问答复用同一组片段，
避免重复索引和三个功能各说各话。

## 2:30—3:35：测验、掌握度与保存

展示一题概念题、一题代码定位题和一个实践任务。
在定位题填写完整仓库相对路径，在实践题填写提交说明，然后离线评估。

解释：定位题用确定规则评分；概念开放题在离线模式下标记待复核；
实践产物始终需要人工复核。掌握度只使用可靠评分，不把用户自述当成已掌握。

点击“保存学习进度”，说明路线、测验结果和掌握度在一个 SQLite 事务中保存。

## 3:35—4:25：贡献准备度

展示五个固定分项：Issue 清晰度、技能覆盖、证据覆盖、测试准备、
贡献流程准备。说明总分由分项相加，可复算，不是 LLM 随意给百分比。

展示 openEuler/openGauss 清单的 `confirmed` 和 `needs_confirmation`，
说明准备度不是 PR 合入概率。

## 4:25—5:00：评测与限制

展示测试和评测结果：20 个检索案例中，16 个来源问题检查 Top-3，
4 个越界问题检查拒答；核心测试离线、无需真实 API。

最后打开 `docs/case-study-openeuler.md`：真实 Plugin #1626 案例证明
目标结构化、规范提醒和测试准备度有价值，也暴露 C++/SQL/Java 尚未索引、
无法替代完整构建和 CI 的限制。

收尾话术：

> RepoMentor 不是替用户完成贡献，而是把学习者、目标 Issue、真实仓库证据、
> 测验和贡献准备度连成一个可解释、可拒答、可持久化的学习闭环。
