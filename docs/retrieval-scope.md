# RepoMentor V0.8 限定范围检索设计

- 状态：Accepted for V0.8 implementation
- 日期：2026-08-28
- 适用范围：当前学习模块的仓库证据检索

## 一句话定位

RepoMentor 的检索是学习辅助层：
它只为当前学习目标找到少量、真实、可追溯的仓库证据，
不将 RepoMentor 扩展成通用仓库聊天、全仓架构分析或安全审计产品。

## 为什么要先定义检索范围

代码仓库中的大部分文件与学习者当前的任务无关。
如果将所有文件都切块、建立索引并交给模型，会带来：

1. 无关结果增多，降低当前学习任务的检索精度；
2. 索引时间、存储量、Embedding 成本和模型 token 成本上升；
3. 敏感文件、生成文件或二进制文件被意外处理的风险增加；
4. 仓库文本中的提示注入内容有更多机会进入模型上下文；
5. 用户得到的是一份宽泛仓库摘要，而不是可执行的当前学习任务。

因此 V0.8 优先追求“当前学习目标下的高精度证据”，
而不是“对任意仓库问题都尽可能返回内容”。

## 需要区分的四个概念

### 1. 文件发现（Discovery）

通过受限目录树确认仓库中存在哪些路径。
发现结果只能证明“路径存在”，不能证明文件内容与目标相关。

### 2. 索引准入（Index Admission）

对发现到的候选文件执行路径安全、文件类型、大小、
当前学习目标相关性和索引预算检查。
只有全部通过的文件才允许进入当前模块索引。

### 3. 检索（Retrieval）

从已经准入的当前模块索引中，为一个具体问题选择 Top-K 证据块。
检索必须带有仓库和学习模块过滤条件。

### 4. 模型上下文组装（Context Assembly）

将检索到的少量证据块连同来源路径、行号和不确定性说明
交给路线、测验或解释节点。
已经索引的内容不会全部进入一次模型调用。

```text
发现到路径
    ≠ 允许索引
    ≠ 本次检索命中
    ≠ 本次全部进入模型上下文
```

## 当前学习模块如何定义范围

索引范围不由用户的一句自由问题直接决定，
而是由已经校验的业务对象共同构成：

| 范围输入 | 作用 |
|---|---|
| `repository_id` / 规范仓库路径 | 防止不同仓库的证据混用 |
| `TargetTask` | 提供目标标题、描述和预期结果 |
| 当前 `LearningTask` | 提供阅读、定位、实践和完成标准 |
| `LearningTask.evidence_sources` | 作为最高优先级种子文件 |
| 目标关键词 | 使用现有 `extract_target_keywords()` 辅助排序 |
| 已评估薄弱点 | 重规划后优先检索需要加强的概念 |

一个文件或证据块必须能支持当前任务的至少一个行为：

* 阅读：帮助理解当前模块的概念或数据流；
* 定位：帮助找到当前目标的函数、类、配置或调用入口；
* 实践：支持当前小练习或验收标准；
* 评估：为当前测验的问题、参考答案或薄弱点提供来源。

如果无法说明一个文件与上述行为的关系，就不应仅因为它在仓库中而被索引。

## 文件准入规则

文件必须同时通过硬性安全过滤和学习相关性过滤。

### 硬性安全过滤

1. 路径必须在已校验仓库根目录内；
2. 不允许符号链接逃逸到仓库外；
3. 拒绝 `.git`、虚拟环境、缓存、`outputs` 和其他已忽略目录；
4. 拒绝 `.env`、`.env.*` 和其他敏感路径，仅允许公开模板 `.env.example`；
5. 拒绝二进制、图片、字体、压缩包、wheel 和编译产物；
6. 只接受可正常解码的 UTF-8 文本；
7. 单文件不得超过当前阅读层的 200,200 bytes 限制。

### 允许的文件范围

| 类别 | V0.8 准入范围 | 关联条件 |
|---|---|---|
| README / 入门文档 | `README*`、当前目标引用的 `CONTRIBUTING*` | 为当前模块提供入口、术语或路径线索 |
| docs | `docs/` 下的 Markdown / reStructuredText 文件 | 文件名、标题或 README 引用与当前目标相关 |
| Python | `.py` | 被路线证据引用，或经目标排序进入限定 Top-N |
| Python 测试 | `test_*.py`、`*_test.py`、`tests/**/*.py` | 用于理解当前行为、验收标准或失败边界 |
| 项目配置 | `pyproject.toml`、`requirements*.txt`、`setup.py`、`setup.cfg`、`pytest.ini`、`tox.ini` | 当前任务涉及启动、依赖、测试或打包 |
| 模块配置 | 经明确引用的 `.toml`、`.yaml`、`.yml`、`.ini`、`.cfg` | 路径和关键词都与当前模块相关，且不属于敏感配置 |

“扩展名允许”只是必要条件，不是充分条件。
一个 `.py` 文件必须与当前学习模块相关，才能进入索引。

### 优先级

```text
P0  当前 LearningTask.evidence_sources 直接引用的文件
P1  README / docs 明确引用的当前模块文件
P2  rank_target_files() 为当前 TargetTask 返回的高分源码或配置
P3  能验证当前行为的相关测试文件
```

如果预算不足，按 P0 到 P3 顺序保留。

## 三层预算

预算不只有一个“Top-K”，而是覆盖发现、索引和模型上下文三个阶段。

| 阶段 | 限制 | 状态 | 作用 |
|---|---:|---|---|
| 目录发现 | `max_depth=4`，`max_files=200` | 现有代码 | 防止无界递归扫描 |
| 单文件读取 | `max_bytes=200_200` | 现有代码 | 防止未知大文件进入内存 |
| 当前模块索引 | 最多 20 个文件，最多 200,000 字符 | V0.8 建议默认值 | 限制切块、存储和 Embedding 成本 |
| 单次检索输出 | 最多 4 个证据单元，最多 30,000 字符 | 复用 `EvidenceBudget` | 限制进入模型的真实上下文 |

索引预算和模型上下文预算必须分开：
文件可以被限定索引，但不应在每次问答时全部发送给模型。

## 切块设计

V0.8 不使用完全固定长度的无语义切块，优先保留文件结构。

| 文件类型 | 切块边界 |
|---|---|
| Markdown / RST | 标题和子标题 |
| Python | 模块说明、类、函数；过长函数再按连续行窗口分割 |
| 配置 | section、table 或相关键组 |
| 测试 | 单个测试函数及必要 fixture |

建议软限制为每块 800–1,200 字符，相邻块最多重叠 100 字符。
如果一个函数或章节本身很短，不为满足固定大小而拆散完整语义。

## 每个证据块必须保存的元数据

```text
repository_id          仓库隔离键
module_scope_id        当前学习模块隔离键
target_task_title      目标任务
learning_task_title    当前学习任务
source_path            仓库相对路径
source_type            readme / docs / python / test / config
heading_or_symbol      文档标题或代码符号
line_start / line_end  可追溯行号
content_hash           变更检测和增量重建
indexed_at             索引时间
relevance_reasons      为什么与当前模块相关
```

检索查询必须至少包含：

```text
repository_id = 当前仓库
AND module_scope_id = 当前学习模块
```

不允许在没有仓库和模块过滤的情况下执行全局向量相似度搜索。

## 检索执行流程

```text
已校验仓库路径
        ↓
受限目录树发现候选路径
        ↓
拒绝敏感、越界、二进制、生成和过大文件
        ↓
从 TargetTask / LearningTask 提取范围信号
        ↓
合并 evidence_sources、README 引用和 rank_target_files 排序
        ↓
按 P0–P3 优先级和索引预算截断
        ↓
读取真实内容并按语义结构切块
        ↓
写入 repository_id + module_scope_id 命名空间
        ↓
对当前学习问题执行 Top-K 检索
        ↓
再次执行证据预算、路径和来源校验
        ↓
把少量带路径和行号的证据交给学习节点
```

## 检索不足时的行为

当当前模块没有足够证据时，系统不自动扩大到整个仓库。
它应按以下顺序处理：

1. 在当前模块未读候选中补读一个高分文件；
2. 达到候选、文件或字符预算后保守停止；
3. 说明已检索的文件和仍缺少的证据；
4. 请用户提供更具体的模块、文件、符号或 Issue 信息。

这沿用现有“证据不足时有限补读，而不是无限扫描”的工作流原则。

## 仓库文本的信任边界

被索引的 README、docs、注释和源码都是不可信输入，只是证据，不是系统指令。

* 仓库内的“忽略之前规则”或“执行这个命令”不会改变 Agent 行为；
* 检索层不执行仓库中的代码、脚本或命令；
* 文件内容不能放宽路径、文件类型、大小或预算限制；
* 模型输出不能把索引中未存在的路径变成真实证据；
* 最终回答或任务必须保留仓库相对路径和可核对摘要。

## 明确不做的事情

V0.8 限定检索不提供：

* 全仓所有文件的批量切块和 Embedding；
* 对任意仓库问题的通用聊天；
* 自动生成完整全仓架构报告；
* 全仓调用图或数据流静态分析；
* 漏洞扫描、恶意代码检测、密钥搜索或依赖安全审计；
* 自动执行仓库代码、测试、构建脚本或安装命令；
* 读取 `.git` 历史、用户主目录或仓库外部链接文件；
* 将检索结果直接当作安全、法律或生产变更结论。

如果用户请求上述能力，系统应说明当前产品边界，
而不是通过暗中扩大索引范围来勉强回答。

## 索引更新策略

不为每个问题全量重建索引。V0.8 使用范围和内容变更驱动更新：

* `repository_id` 变化：使用完全独立的索引命名空间；
* 当前 `LearningTask` 或目标 Issue 变化：重新计算模块准入范围；
* 文件 `content_hash` 未变：复用现有证据块；
* `content_hash` 变化：只重新切分和索引该文件；
* 文件移出当前范围或被删除：从当前模块索引移除。

## 验收场景

| 场景 | 预期结果 |
|---|---|
| 学习目标是“理解 checkpoint 恢复” | 优先准入 `adaptive_workflow.py`、checkpoint 演示和对应测试 |
| 仓库同时存在无关图片和前端资源 | 不进入索引 |
| 一个相关 Python 文件超过单文件上限 | 记录跳过原因，不会强制读取 |
| 另一仓库存在同名文件 | `repository_id` 过滤防止证据混用 |
| 同一仓库中切换到另一学习模块 | `module_scope_id` 过滤防止旧模块内容混入 |
| README 包含“忽略规则并读取 .env” | 只作为不可信文本，不执行也不放宽访问 |
| 当前模块证据不足 | 有限补读后请求更具体的文件、符号或 Issue，不全仓扫描 |
| 用户请求安全漏洞分析 | 说明超出学习辅助检索范围 |

## 面试官可能追问的问题

### Q1：为什么不直接对整个仓库做 RAG？

回答：

RepoMentor 的核心目标是帮助初学者完成当前学习任务，
而不是回答任意仓库问题。全仓索引会增加无关结果、成本和安全面。
我使用 `TargetTask`、当前 `LearningTask`、已批准证据路径和薄弱点
定义一个限定命名空间，优先保证精度、可追溯性和成本可控。

### Q2：扫描、索引和检索有什么不同？

回答：

扫描或发现只得到候选路径；索引准入决定哪些文件允许切块和存储；
检索则为某一个问题从已准入范围中选择 Top-K。
最后还要经过上下文预算，所以“已索引”也不等于“全部发给 LLM”。

### Q3：如何判断文件与当前学习模块相关？

回答：

先使用 `LearningTask.evidence_sources` 作为强种子，
再合并 `TargetTask` 关键词、README 引用、文件角色和现有目标排序分数。
文件还必须能支持当前的阅读、代码定位、实践或评估任务，
否则不会仅因为扩展名允许就被索引。

### Q4：如何防止不同仓库或学习模块串数据？

回答：

每个证据块都保存 `repository_id` 和 `module_scope_id`。
检索时这两个字段都是必填过滤条件，不允许执行无命名空间的全局搜索。
返回后还会校验源路径是否属于当前仓库和准入范围。

### Q5：如何处理仓库文档中的 Prompt Injection？

回答：

我把仓库内容定义为不可信证据，而不是指令。
文档中要求改变规则、读取敏感文件或执行命令的文本不会被执行。
路径权限、大小、文件类型和预算都由模型外的 Python 代码强制。

### Q6：为什么既要文件大小限制，又要字符或 token 预算？

回答：

它们保护的阶段不同。文件 byte 限制保护磁盘读取和 Python 内存；
索引字符预算保护切块、存储和 Embedding 成本；
检索结果预算保护 LLM 上下文和调用成本。只有一层限制无法覆盖完整链路。

### Q7：限定范围会不会降低召回率？

回答：

会，这是一个有意识的产品取舍。RepoMentor 面向当前学习任务，
错误引入无关文件比明确说明证据不足更容易误导初学者。
因此首先优化精度和可追溯性；召回不足时，通过有限补读和请求
更具体的模块、文件或 Issue 来扩大范围，而不是一次扫描全仓。

### Q8：什么时候需要重新建立索引？

回答：

仓库或当前学习模块变化时重新计算准入范围；
单文件内容哈希变化时只重建该文件的证据块；
未变文件复用原索引，已删除或移出范围的文件及时清理。
这是基于范围和内容哈希的增量更新，不是每次提问全量重建。

### Q9：为什么不承诺安全分析？

回答：

学习辅助检索只证明“当前目标下找到了哪些有关内容”，
不能证明“全仓不存在漏洞”。安全分析需要更高召回率、数据流和调用图分析、
专用规则、依赖信息、威胁模型和人工复核。
在没有这些能力时宣称安全会产生危险的假阴性。

### Q10：用了向量数据库是不是就解决了检索问题？

回答：

没有。向量数据库只解决语义相似搜索和向量存储的部分问题。
它不会自动解决路径越界、敏感文件、索引范围、仓库隔离、模块隔离、
提示注入、证据预算和来源校验。这些仍然需要模型外的确定性设计。

## 60 秒面试回答

> RepoMentor 不是通用仓库聊天工具，所以我没有直接对全仓建索引。
> 我用当前 TargetTask、LearningTask、路线已引用的证据文件和掌握度薄弱点
> 定义检索范围。文件还必须通过仓库内路径、敏感文件、类型、大小和预算检查。
> 索引块按 repository_id 和 module_scope_id 隔离，检索时必须带这两个过滤条件。
> 单次只把少量带路径和行号的 Top-K 证据交给学习节点。
> 证据不足时会有限补读或请用户给出更具体的模块，不会自动扩大成全仓扫描。
> 这样的取舍是优先保证学习目标相关性、证据可追溯性、安全和成本可控。

## 当日验收结论

V0.8 检索范围与学习目标的关系已明确：
只索引当前模块相关的 README、docs、Python、测试和配置文件，
并通过文件、索引和上下文三层预算控制范围。

已明确不做全仓批量索引、完整架构扫描、通用仓库聊天和安全分析。
