# RepoMentor Prompt实验记录

## 实验目标

比较三种Prompt对个性化程度、目标相关性、文件真实性和任务可执行性的影响。

## 固定输入

- 使用同一个用户资料；
- 使用同一个目标任务；
- 使用同一个README；
- 使用同一个目录树；
- 使用同一个模型和Temperature。

## 发现的问题

### V1

把虚拟目录树误当成用户当前拥有的真实仓库；
大量无证据断言源码内部结构；
任务和完成标准几乎全部依赖当前不可访问的源码。

### V2

v2相对V1的实际改善：

更充分地使用了用户画像；
明确了 RAG不属于当前目标；
明确了 LangGraph、决策机制、运行方式和测试内容均待确认；
任务结构更容易阅读；
时间安排更清楚；
对空测试目录进行了条件处理。

问题：
默认用户拥有真实源码；
默认源码可以运行；
默认文件内部具有特定职责；
任务仍以代码阅读和修改为主；
没有在生成路线前检查证据可用性；
“需确认事项”没有真正约束主体输出。
明知多项信息待确认，仍安排依赖这些信息的任务；
没有识别当前源码不存在这一最高优先级条件；
更完整的格式掩盖了路线整体不可执行的问题。
### V3

问题:
明确知道源码信息未知，却仍生成完整源码阅读路线；
将虚拟目录中的路径称为“真实文件”；
“证据驱动”主要改善了说明方式，没有解决任务可执行性这一根本问题。

## 当前结论

三版中，V3证据驱动版综合表现最好。

V3主要在以下方面优于另外两版：

1.用户能力分析更完整；
2.目标任务拆解更清楚；
3.每个推荐文件都有依据说明；
4.会明确标记基于目录命名的推断；
5.明确指出 LangGraph 没有证据；
6.明确指出模型决策机制未知；
7.对输入方式、外部依赖、测试目录和函数命名进行了风险说明；
8.学习产物设计更系统；
9.完成标准更强调代码证据；
10.能够较好地区分事实、推断和未知。

相对 V1，V3改善了：

从隐式使用用户资料变为显式能力分析；
从直接断言文件职责变为部分标记推断；
从少量不确定性说明变为完整风险清单；
从简单七天任务变为有依据、有产物、有时间预算的结构；
明确纠正了“LangGraph 不熟悉不代表仓库使用 LangGraph”这一问题。

相对 V2，V3改善了：

推荐文件时提供单独的依据；
更明确地区分 README 信息和目录命名推断；
对“模型决策”一词进行了专门分析；
增加疑问清单、假设表和 Trace；
对测试目录、外部服务和输入方式的未知说明更完整；
完成标准更强调每个断言对应代码位置。
